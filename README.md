# Linux Mini Shell

A Unix-style shell implemented in C as a systems programming project for *COP 4610 — Operating Systems Principles* course at Florida International University.

## Project Overview

This project demonstrates core operating systems concepts through the implementation of a lightweight command-line shell. The shell supports external command execution, built-in commands, input/output redirection, and a single pipeline between processes.

## Features

- Execute external commands using `fork()`, `execvp()`, and `wait()`
- Built-in commands: `cd`, `pwd`, and `exit`
- Output redirection with `>`
- Append redirection with `>>`
- Input redirection with `<`
- Single pipeline support with `|`
- Error handling for invalid commands, directories, files, and process creation
- Linux process and system-call analysis using `strace`, `ps`, and `/proc`

## Usage Examples

Run external commands:

```bash
mysh> ls -l
mysh> echo hello world
```

Use built-in commands:

```bash
mysh> pwd
mysh> cd /tmp
mysh> exit
```

Redirect standard output to a file:

```bash
mysh> echo hello > output.txt
```

Append output to an existing file:

```bash
mysh> echo world >> output.txt
```

Redirect standard input from a file:

```bash
mysh> wc -l < output.txt
```

Connect two commands with a pipe:

```bash
mysh> ls -l | grep .c
```

## How It Works

The shell continuously reads user input, determines the type of command being requested, and executes the appropriate operation.

### External Commands

External programs are executed by creating a child process with `fork()`. The child replaces itself with the requested program using `execvp()`, while the parent shell waits for the child to finish before displaying the next prompt.

### Built-in Commands

Commands that must modify the shell process itself are handled directly without creating a child process:

- `cd` changes the shell's current working directory.
- `pwd` displays the current working directory.
- `exit` terminates the shell.

### I/O Redirection

Redirection is implemented using Linux file descriptors:

- `>` redirects standard output and overwrites the destination file.
- `>>` redirects standard output and appends to the destination file.
- `<` redirects standard input from a file.

The shell uses `open()` to access the requested file and `dup2()` to replace standard input or standard output before executing the command.

### Pipes

A single pipeline connects two processes using `pipe()`.

For a command such as:

```bash
mysh> ls -l | grep .c
```

the shell:

1. Creates a pipe.
2. Forks a child for the left command.
3. Redirects the left child's standard output to the pipe.
4. Forks a child for the right command.
5. Redirects the right child's standard input from the pipe.
6. Closes unused file descriptors.
7. Waits for both child processes to finish.

## Process and System Call Analysis

The project also included observing the shell at the operating-system level using Linux diagnostic tools.

### `strace`

`strace` was used to inspect system calls generated by the shell and its child processes, including:

- `execve`
- `clone` / process creation
- `pipe`
- `dup2`
- `wait4`

This made it possible to connect the C implementation directly to the system calls executed by the Linux kernel.

### `/proc`

The Linux `/proc` filesystem was used to inspect running processes and their open file descriptors.

This was particularly useful for analyzing pipe behavior and understanding why a process can remain blocked when a pipe's write end is unintentionally left open.

### `ps`

`ps` was used to inspect process IDs, parent-child relationships, and process states while commands were running.

## Limitations

This project intentionally implements a small subset of full Unix shell functionality.

Current limitations include:

- Only one pipe per command line
- No combination of pipes and redirection in the same command
- No wildcard expansion
- No environment-variable expansion
- No command history
- No background execution
- No quoted-string parsing
- No job control

These limitations reflect the educational scope of the project and its focus on operating-system concepts such as processes, file descriptors, and inter-process communication.
